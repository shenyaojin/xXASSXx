# 结果检查指令校验修复

2026-10-07，用户提供 pengchao 终端截图：远端已经返回材料分析结果，发起方在结果检查阶段显示 `invalid review decision`，任务停在需要处理。

## 原因与修复

旧 `task_decision` 工具将 action 定义为不受约束的字符串，并向所有阶段暴露相同字段。模型响应的重试只覆盖工具调用结构和 JSON 解析；只要 JSON 合法，就提前记为 succeeded 并退出重试。直到结果检查分支才判断 action，此时错误会直接让任务进入需要处理。截图中的错误来自这个分支。未访问 pengchao 本机的原始模型响应，因此不推断它究竟返回了哪个错误 action。

现在按需求整理、问题处理、结果检查、对话回复分别给出合法 action 枚举和字段。Rust 在模型调用的重试范围内校验实际响应，包括阶段、必要字段、非空正文、草稿交付项和操作类型；不只依赖模型遵守工具参数约束。

不合格响应记录为失败，并将具体校验原因告知模型，按原有上限重试。不会把未知动作猜成 complete，也不会因重答重跑已完成的文件执行。耗尽次数时保留结果、显示可理解的错误，允许用户从当前步骤恢复。

## 验证

- 全部默认自动测试 114 项通过，2 项既有 opt-in 测试按默认配置忽略。格式检查、Clippy 和优化构建通过。
- 模拟回归验证：连续两次返回属于 resolve 阶段的 answer 动作，review 自动纠正后完成；连续三次错误时不归档、不提交完成通知、不保存成功决策；显式恢复保留候选及既有执行，随后完成同一修订。
- 真实 DeepSeek、官方 Codex、同机两个隔离个人端及回环信箱，通过实际可交互 PTY 发起任务、确认、恢复并看到最终答复。不是双机部署，也未向 pengchao 发送测试任务。
- 真实任务 `T-2943cc63`：读取两个合成配置的 iterations，终端显示 10、100、差值 90，并解释仅凭配置不能证明准确性；两个参与端完成归档，发起端无物理文件执行。独立核对来源字节数和 SHA-256 一致。
- 实测中第一次材料冻结检测到源文件元数据变化而暂停；保留记录，通过 TUI 的 CtrlY 恢复原执行方后完成，没有修改检查条件或填库。此中断与 review action 错误分开记录。
- 错误 action 的稳定复现来自模拟回归；真实模型这次没有自然返回该错误。精简证据见 [验证记录](review-decision-fix-evidence.json)，终端画面和原始记录位于被忽略的 `smoke-output/review-decision-real-88cc492c/`。

## 旧版本的临时恢复

对截图中的任务，可在发起方 pengchao 的 TUI 按 CtrlT，选中任务并进入，再按 CtrlY 重试结果检查。该动作复用已有候选结果，不要求新建任务或重新确认需求。旧版仍可能再次收到不合法的模型动作；失败时保留任务，不能据此宣称结果已经完成。

本次修复已在仓库实现和验证，尚未发布、替换现用二进制或更新朋友的安装。修复必须进入后续安装包，旧客户端才会获得自动校验重试；升级前保留个人身份、配置和历史，不重新初始化。
