# 整项任务批准与聊天接续验收

日期：2026-10-15（America/Denver）。0.9.0-alpha 开发候选；日常安装尚未升级。

## 修复的是通用流程

原来“允许写入/运行”只开放独立目录，实际 Codex 仍禁止联网和凭据操作；聊天答案可能落成补充，模型又称任务已经继续。现在一次本机批准绑定任务及版本，执行、Codex 权限和指定成果发送共用授权。聊天答案绑定发送时的真实问题，保存用户原话，执行端收到后续接原会话；普通状态答复使用持久状态，转交用户的问题保留执行端原文。

代码没有按 SSH 公钥、项目名或某条例句设置分支。阶段附件适用于先交付材料、等待外部动作、再继续的任务。真正未知的业务选择仍需要回答，任务目标变更后的新版本仍要批准，旧受限授权不会自动扩大。

## 自动回归的覆盖范围

| 场景 | 检查内容 |
| --- | --- |
| 一次批准、多阶段执行 | 阶段成果自动授权；回答后复用批准；最终输出可位于默认任务目录之外；设备仍为 Ask |
| 模型错误状态或追加审批 | 即使模型声称已继续，真实未答问题仍显示等待；不得把转述中新加的审批问题展示给用户 |
| 多个待答问题 | 一次回答只解除对应问题，其他问题保持等待 |
| 重复、过期及错任务答案 | 重复事件幂等；不能跨任务、跨版本或绑定后来替换的问题 |
| 旧授权与撤销 | schema 11 迁移不扩大旧权限；明确重新批准才扩大；撤销会停止运行进程 |
| 网络中断与附件 | 未送达不能伪装已接收；消息和文件去重恢复、丢失回执恢复、字节校验 |
| 取消与恢复 | 旧进展不恢复已停止任务；结果不确定的运行不盲目重放；重试结果检查不重做执行 |

上述测试使用模拟模型和执行夹具，验证内核行为，不代表真实模型在任意业务上的正确率。最终提交的 CI、真实模型和终端证据分别记录在精简证据中。

## 真实跨机器流程

Lakota 为发起端 a、Trader 为执行端 b，两个隔离配置均为 Ask for approval。使用真实 DeepSeek、官方 Codex 0.162.1、两端实际交互 PTY、认证信箱及经 SSH 隧道连接的专用 Git SSH 服务。任务数据是可独立核对的合成仓库，不涉及量化项目。SSH 服务和仓库的准备属于外部测试环境；密钥生成、仓库克隆、依赖安装、计算及成果传送由任务内的 Codex 和 xXASSXx 完成。

首轮任务 `cc5f7d71-635b-5157-acaf-14732004aa5c` 完成了两阶段交付，但发起端模型转述问题时追加了“第二阶段是否再批准”。修复为显示执行端持久保存的原问题，保留首轮记录并重新从新任务、新专用密钥、新克隆目录开始复验。首轮真实执行还发现缺少 Python venv 支持，执行端依批准安装依赖后完成，未要求第二次批准。

最终复验任务 `7fe9309a-aa83-5635-9908-b1dc13d8e874` 始终为第 1 版：

本轮证明该类任务在真实授权、阶段交付、聊天回答和断线恢复链路上完成；不把两次合成任务扩大成任意业务零错误的承诺。依赖或服务本身不可用、任务要求含糊、模型无法完成业务时，仍可能需要处理。自动回归矩阵用于防止已知状态与授权故障复发，不能替代具体成果的质量判断。
