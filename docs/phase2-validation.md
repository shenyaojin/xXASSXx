## A：迁移与知识版本

新增 schema 2，保留第一阶段任务、结果、运行、会话和原始事件。迁移测试实际构造 schema 1 的成功任务、执行和事件，重复初始化两次，核对原记录可读。

已通过以下验收：

- 发布目录 V1/V2 后删除源目录，仍准确导出旧二进制内容和空目录；差异识别新增、删除与变化项。
- UTF-8 决策原文发布与取回；版本行更新被 SQLite 触发器拒绝。
- 两个独立连接同时以相同旧 main 发布，只有一个成功，历史只有一个新版本。
- 同 request_id 同请求返回原版本；不同内容/父版本冲突，跨对象父版本拒绝。
- 修改或删除 blob 导致校验失败；损坏内容不生成有效导出；已存在目录拒绝覆盖。
- 发布遇到损坏的已存在 blob 或不支持的源时，不暴露不完整版本。
- 拒绝符号链接、特殊文件、自身运行状态、绝对路径及路径逃逸。

额外逐条执行 README 时，前两次新文件发布被源变化保护拒绝，旧版保留；后续完整示例通过。进一步对 20 次刚写入文件的发布取证，观测到一次文件大小和 mtime 不变、ctime 在读取期间变化约 6 ms，程序安全拒绝。未确定修改 ctime 的外部进程；保留严格检查，README 已说明后台文件属性变化也需要重试。

文件写入使用流式哈希、临时文件、同步落盘、不可覆盖的内容地址，完成后才提交版本/main 事务。代码检查读取前后文件/目录标识变化；没有承诺活跃写入目录的原子快照，也没有完成断电、磁盘耗尽或恶意同用户 TOCTOU 注入测试。失败允许留下未引用 blob，无 GC。

## B：独立成员与真实 HTTP

测试启动实际 Rust 信箱进程，A/B/C 使用三个不同路径的 SQLite，A 无法从自己数据库读到 B 的对象行。已验证：

- A 保存发件箱，经 HTTP 投递，B 离线时本地收件箱为空；重启信箱后 B 仍能领取。
- 实际请求、回复、追问回到同一 conversation；按当前版本解析为 V2 后再发布 V3，原请求继续使用 V2。
- 重复 message_id / ACK 丢失不会产生第二条本地有效消息；冲突内容拒绝。
- 无凭据拒绝访问；不能伪造发送成员；C 不能确认 A→B 消息，C 的收件箱为空。
- 关闭会话保留原文、拒绝继续回复；关闭模型不影响基本消息收发。

relay 和本地数据库分别保存状态，接收端先提交再 ACK；不声称 exactly-once。静态成员配置、独立凭据和 HTTPS URL 检查已实现，没有实测跨机器反向代理或公网部署。

## C：真实协议适配与受限模型循环

模拟 HTTP 服务接收实际 Chat Completions 请求，返回函数调用；Rust 执行业务工具，将对应 `tool_call_id` 的结果回传，服务再生成下一轮请求。不是通过测试直接修改数据库来伪造模型动作。

已核对多个工具调用顺序、工具调用 ID、后续轮次 `reasoning_content`、原始消息与独立摘要。上下文不包含作为哨兵的文件正文或本地数据目录。已验证明确元数据查询无需模型、缺 key 可见、额度限制、超时、无效响应、非法工具参数和工具轮数限制，失败后用新一轮模型运行重试可成功，原消息保留。

模型通过事务性委托工具重复请求两次，仍只建立一个任务。Rust 工具没有 shell、代码、文件修改或 SQL 接口；同伴请求只允许其明确引用的 shared 对象，模型不能选择无关会话或第三联系人。执行记录中的本地目录不进入模型工具结果。

真实适配器依照实现时的 DeepSeek 官方 [工具调用](https://api-docs.deepseek.com/guides/tool_calls/) 和 [Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/) 文档实现非流式 HTTP、响应解析与多轮工具结果关联，业务模型名称可配置。已用真实 DeepSeek 验证下述查询与回复流程；未安装或验证任何具体本地模型服务。

## D：Codex 委托、MCP 与完整演示

委托执行调用保留的 `run-once` 监护器与任务锁。测试中的模拟 Codex 真正启动 Rust 任务 MCP，执行初始化、`get_task` 和 `submit_task_result`；没有绕开 task/run 校验。随后 Rust 核对完成状态，生成回复，经实际 HTTP 到 A，再由 A 的管家 MCP 读取。

已验证提交结果后进程失败不能发出成功回复；重试复用原 task 和原 session ID，并保存 `resumed_session_id`。已完成委托不重复执行，进程重启/重复处理不重复创建委托或回复。原有强杀 CLI、Ctrl-C、超时进程组清理、预检终止及活跃任务锁测试继续通过。

新增权限回归核对实际 Codex 启动参数：同伴委托不注册主人本地管家 MCP；主人直接提交的任务可注册该服务。任务 MCP 保持原有两项工具；管家 MCP 拒绝 `submit_task_result`。这避免同伴请求借委托获得主人全部私有元数据/其他会话能力。

### 首次真实失败及修复

第一次真实调用已成功获取元数据，但模型在回复中使用“main / 当前解析版本”。原路径防误传检查把独立 `/` 分隔符当作本地绝对路径，连续拒绝 `submit_reply`，最终保存 `model_tool_round_limit`；没有伪造成功或发送回复。失败报告保留在 [首次真实报告](../smoke-output/deepseek-c426e18c-d594-450b-9dff-75f9d843eac2/report.json)。

已修正为允许独立的正文 `/`，继续拒绝 `/Users/...`、`C:\...` 和 `file://...` 等路径。新增实际 HTTP 请求/回复回归验证该边界，模拟模型工具循环也加入同样的斜杠正文。未提高调用预算或放宽任务/版本验收；修复后真实测试通过，本地全套回归增加到 46 项。
