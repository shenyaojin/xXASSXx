# 本地读取与 Codex 交接

更新：2026-10-14。实现提交 `6a04baec7e08d69a139faa6845bf204d4d881e82` 已随 [0.8.0-alpha](https://github.com/shenyaojin/xXASSXx/releases/tag/v0.8.0-alpha) 公开发布；此次未替换日常客户端。下文保留实现提交的功能验收，正式包构建、安装和升级验证另见 [0.8.0 发布证据](releases/v0.8.0-alpha-evidence.json)。

local agent 可以在本机授权范围中列目录、按文件名或小文本内容查找、分段读取文本；同一次请求可以分别查询多个白名单。目录名称和文件内容均视为数据，不改变用户原意或权限。已有固定快照、任务版本和独立执行目录流程保留，各阶段使用其当前绑定范围。

每轮得到工具结果后，按原始交付目标选择下一步：

- 现有工具足够：继续必要的读取；有依据回答时保存答复。已确定的文件可直接准备发送。
- 缺少能力：把原始请求、查询参数、真实工具结果、候选路径与剩余工作交给 Codex。归档／文档解析、代码修改、程序执行、大规模或复杂核验由 Codex 承接。交接理由不能添加用户未要求的目标。
- 缺少人的决定：明确说明无法从资料确定的选择。已有 Full access 时不再逐项请求权限；真实业务歧义仍须澄清。

程序在回复或业务动作成功保存后结束本人对话处理，不再为了收尾多调用一次模型。简单只读执行可以由 local agent 直接提交，内核仍验证当前任务、版本、授权、引用和结果；运行记录不会虚构 Codex 会话、MCP 初始化或进程退出码。需要交接时，同一执行保留实际读取记录；已进入 Codex 的恢复任务继续使用 Codex。

## 文件发送与收件

文件定位、内容核验、实际传输是不同步骤。local agent 已有发送工具时可直接准备附件；需专门解析时交给 Codex。若任务要求本机核验／处理后发给另一位联系人，确认草稿中的 `deliver_to` 单独记录收件人，不把对方变成执行成员。收件人只收到附件，不会收到自己未加入的本机执行任务。收件人字段限定实际成员 ID；显示名或不符合当前执行范围的值在产生副作用前进入有界纠正重试。

附件继续使用 Rust 的固定清单、发送权限、分块传输、哈希和收据。Ask for approval 等待发送端批准清单；Full access 自动继续。完成判断要等匹配当前任务版本、接收人和清单的实际收件确认，不能将候选路径或已准备清单当作送达。

## 工具范围和证据

`list_local_files`、`search_local_files`、`read_local_file` 共用当前本机目录授权。每次调用重新检查，任务执行还检查当前版本和运行授权。符号链接逃逸、路径越界、已撤销范围和凭据／应用私有状态被拒绝；交给 Codex 不扩展权限。

文本文件最多 1 MiB；读取返回实际行号、文件字节数与 SHA-256。目录遍历最多 4096 项，搜索受时间和内容字节预算约束，单次结果文本也有上限；跳过或截断会显式记录。达到局部查找预算时应说明局限或交接，不声称已穷尽全部文件。

交接记录只进入本机执行上下文，带有截断标记和“历史观察”说明；Codex 应重新核对处理所需的候选文件，不将历史记录当作新的授权。新默认模型预算为 8 次请求、7 轮工具、24 次工具调用，已配置的数值保留。

Full access 是设备主人选择的持久本机授权。明确任务、执行和发送可以无人值守继续；Codex 使用 `approval_policy=never` 与完整访问模式。它不会补足缺失的业务决定、登录或模型服务，也不会授权另一台机器。

## 验收记录

Lakota 最终 Linux musl 自动回归为 186 通过、0 失败、3 项 opt-in 忽略；格式、Clippy 和优化构建通过，保留既有 `libc::time_t` 弃用警告。111 份代码／测试／技能／构建输入与提交一致。[精确提交 CI](https://github.com/shenyaojin/xXASSXx/actions/runs/38674076394) 的 Apple Silicon Mac 与 Linux 测试、优化构建及独立安装检查均成功；这是手动 CI，发布步骤跳过，没有发布同版本的新二进制。

自动回归包含多个根、越界／符号链接／撤销／敏感文件拒绝、读取失败后恢复、真实观察随交接保留、无 Codex 可执行文件时 local agent 独立完成、同一次执行转 Codex，以及两种权限模式下本机处理后向指定成员发送并等待匹配收据。模拟模型与模拟 Codex 的这些证据不等于真实模型业务验收。

真实模型路由矩阵的最后一轮在 10/24 项通过后遇到 DeepSeek HTTP 503，未宣称 24 项通过。此前两轮测试夹具问题（只检查第一动作、不完整的虚拟目录）和服务错误均保留。真实两轮工具探针随后通过，但探针不替代完整业务任务。

实际双 PTY、真实 DeepSeek 与官方 Codex 在隔离成员上完成以下场景：

- 早期构建中，local agent 跨两份白名单读取发布说明和索引，排除草稿，直接准备正确 ZIP；Ask 模式在终端批准后送达，没有 Codex 执行。
- 最终提交构建中，本机 local agent 的 8 条实际观察进入 Codex 上下文。Codex 内存读取原 ZIP 中的 CSV，统计为 3 条数据、总和 83；随后原包自动发往另一台机器并收到回执，终端显示数字和真实收件人。发起端 Full access，接收端 Ask，发起任务后没有批准输入。
- 最终提交构建中，向 Trader 隔离成员索取它自己的最终包。执行方 local agent 自己读取两根目录中的说明、提交正确文件并自动回传，两端实际终端均显示最终依据。运行记录无 Codex 版本／会话、无 MCP 初始化／进程退出码，保留实际任务读取和结果提交。两端 Full access，无批准输入。

三批文件逐项核对源文件、发送副本和接收副本哈希一致，原始材料前后不变。失败记录没有删除：包括成功交接后冗余模型调用失败、收件人显示名误填 ID（均已修复），以及有条件发送缺少判据时的业务澄清。明确统计请求在两次 HTTP 503 后，以同一请求重新发起成功；不能据此声称服务错误也能自动恢复。

还有两处措辞限制：历史上传进展仍可能写成“本机会出现接收入口”，而本机向外发送时应指目标成员；远端最终总结把不同根中的草稿称为“同目录”，选件及实际字节正确，但位置描述不精确。最终状态、接收人和统计数字已核对，不将本次验证描述成所有模型表述和界面问题均已解决。

原始文件与实际 PTY 画面保存在 Git 忽略的 `smoke-output/local-agent-20261014/` 及两端同名隔离测试目录；[精简证据](local-agent-handoff-evidence.json) 区分早期／最终构建、失败、模拟回归及真实模型结果。隔离后台、信箱与隧道已停止，日常客户端未改。
