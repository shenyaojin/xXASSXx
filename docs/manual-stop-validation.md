# 手动停止与归档验收

日期：2026-10-13。版本：本地安装批次 `0.6.3-alpha`。保留之前未提交修改；本轮未提交、推送或公开发布。

## 交付范围

任务对话和任务列表支持 CtrlX，另有 `/stop`；进行中列表按 `a` 进入相同表单。填写必需的停止原因，Tab 选择“停止并归档”或“仅停止”，Enter 确认，Esc 返回并恢复原输入。任务已变化时拒绝旧表单，保留原因供用户重新确认。明确的停止短语打开表单，不借助模型擅自解释并执行。

发起人停止整个任务；参与方停止本机参与，并使用兼容的 progress 通知发起人。参与方无权向其他成员发全局 cancel。原因、时间、历史、文件保留，归档是个人列表偏好，不代替其他成员归档。恢复显示不恢复执行；参与方退出后，原版本的重试不能重新启动，须由发起人修改并确认新版本。

停止与命令、消息、归档在同一数据库事务落地，不等待后台模型队列。运行中的本机执行通过版本／状态授权检查退出；等待中的模型调用被取消，迟到状态不能覆盖已停止状态。远端离线时要等收到通知才停止，已生成文件不回滚。

## 真实终端与模型

使用实际可交互 PTY，从界面发起任务、确认、操作停止，并亲自查看有意义的结果。保存 ANSI、中文文本和终端单元格；PNG 来自实际记录绘制，未把模拟单元测试当作实机界面，也没有接管用户原有 Terminal 窗口。

2. A 对上述任务选择“仅停止”，填写“已收到停止说明，结束这次试用。”。A 已停止且未归档，B 保留原归档。A 没有替 B 恢复或删除记录。
3. A 新建普通本机只读任务并 CtrlS 确认。真实 DeepSeek／官方 Codex 完成发现、分析两轮，任务 `f5f39ba6-18c8-5e9f-939d-558e697bf2a7` 最终界面准确返回 STOP-7391、37 和实际来源，66 字节原文件哈希未变。此流程验证停止功能没有破坏正常完成路径。
