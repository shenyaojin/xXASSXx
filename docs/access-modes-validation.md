# 访问模式和手动重连验收

日期：2026-10-13（America/Denver），候选版本 0.7.0-alpha，内置技能 0.1.2。源码未提交、推送或公开发布。当前功能以实际本机权限为准，历史默认只读描述不代表用户显式选择 Full access 后的能力。

## 实际终端、模型与文件

在 Lakota 启动两个隔离成员的实际交互 PTY、独立信箱、真实 DeepSeek 与官方 Codex 0.162.1。任务为 `b459467e-75cd-5f77-a9d6-df035851bf05`，只操作预先创建的测试文本，不修改日常 DSS 项目。

1. A 从 `/access` 选择 Full access 后输入一个完整任务；无需 CtrlS。B 仍为 Ask for approval 时，任务等待本机允许，Codex 运行数和独立目录授权数均为 0，证明 A 不能替 B 提升权限。
2. B 在实际终端选择 Full access，任务自动继续，无 CtrlG、无附件批准。Codex 从独立 HTTP 服务取得 value 83，直接修改既有 `work/original.txt`，并修改原白名单目录外的 `outside.txt`。两个文件通过产品传输到 A，来源与收件副本哈希相同，没有人工复制替代业务发送。
3. 执行中关闭隔离信箱，B 终端显示离线并输入 `/reconnect`；恢复信箱后，两端通过同一命令恢复同步。首次断线前后后台实例保持不变，Codex 总计一次成功执行，网络读值一次，没有重放；最终两端任务均为 completed。A 实际终端有 value 83 和两文件收件说明。
4. B 切回 Ask for approval，重启后台后保留设置；没有遗留 `task_workspaces` 永久授权。测试命令在后台停止时也能重新启动后台。

真实模型运行号为 `8066dce4-435d-4165-a3a3-c5cd20154229`。两个文件分别为 3 和 61 字节。此测试验证实际文件写入、联网、授权差异和自动交付，不把测试文本称为本轮重新运行 DSS 科研流程。之前 DSS 的真实成果交接证据仍见 [技能场景矩阵](skills-matrix-validation.md)。

## 发现与验证边界

首次恢复后的同步曾出现短暂 HTTP 400，随后恢复；隔离信箱日志也记录数据库锁争用。原响应正文未保存，不能证明此次 400 或用户先前的断线一定由锁引起。源码确认旧信箱可能把锁争用误报为 400，因此增加只匹配准确锁错误正文的兼容处理，并用真实 HTTP 自动测试区分锁错误与无效请求；没有将任意 400 一律无限重试。最终客户端仍兼容日常旧版信箱。

上述真实任务先于最后的锁错误兼容、连接提示清理和自动确认等待文案修正完成；最终构建另核对终端和连接，不把分阶段证据说成全部在最后二进制重跑。Lakota 系统负载在最终构建期间超过 1000，隔离及日常请求都有超时，保留原始记录；最终隔离两端与日常两端都已观察到恢复连接。手动重连不能修复尚未恢复的服务器或网络。

## 最终构建与安装

173 项自动回归通过，0 失败、2 项既有忽略；格式、Clippy、Apple Silicon 与 Linux musl 优化构建通过，128 份源码／测试／技能及构建文件一致。Mac 与 Lakota 日常客户端均备份后手动安装 0.7.0，停止后的全部数据库表和配置前后相同。没有使用更新器，没有启用日常 Full access。两端实际模式选择器及重连成功界面已保存。

最终 Lakota PTY 验收首次快速粘贴命令被终端误读为 `[200~/reconnect`，产生一条失败的普通助手输入，未产生新业务任务或文件操作；记录保留。随后改为逐个等待真实终端处理、键入原始字符，两条命令均由客户端本地正确处理。这不是业务重放，也未通过修改数据库清除或伪造记录。

备份位于两端 `~/.local/share/xxassxx/backups/access-070-20261013/`。安装包及 SHA256SUMS 在本机 `dist/v0.7.0-alpha/` 与 Lakota 留存并验证；本机临时工具链、编译缓存与测试 Python 依赖已清理，仓库无 target。未操作其他成员电脑或升级 Trader 信箱。
