# Lakota 聊天错误排查与验收

日期：2026-10-14（America/Denver）。基于已发布 0.7.0-alpha，源码起点 `549b7fe`。本轮验收在提交前完成，尚未发布安装包或安装到日常客户端；程序版本未提升，内置技能源码为 0.1.3。日常 Lakota 程序、资料、已取消任务和错误记录保留。

## 原始记录与原因

只读检查 Lakota 日常个人库的任务、运行、MCP 返回、命令事件和后台日志，没有以最终状态替代过程检查。

| 记录 | 观察及根因 | 修复 |
| --- | --- | --- |
| `59f288f4-7194-533b-9830-a98ae0eddb22`，`what can you do` | 普通能力问答被派为 analysis/discover。模型已有无需项目文件的答复，但六次空文件提交被“至少一个可冻结文件”校验拒绝，反复追问；另有一次只输出自然语言而未有效提交的 `missing_result`。用户最终取消。 | 放行非文件/无匹配的空清单，跳过空快照，直接交由发起方审核。候选仍保留成员与提交时间，并明确“没有文件引用”，不编造路径、哈希或搜索事实。非空材料仍走原冻结流程，文件预算与引用检查保留。 |
| `3a8eedba-aa32-514f-90e6-d61d48e724b9`，反演任务 | 执行过程中本机主人输入 `can you prepare some figures to him`。参与方修改目标被正常拒绝，但通用错误处理又将整个任务设为待处理，随即触发运行的 `authorization_changed`。 | 删除“任何 chat/revision 错误都暂停任务”的兜底。命令错误单独显示；准备失败由 prepare_model 只标记自己仍有效的同版草稿，执行失败仍由原调度处理。未赋予参与方修改发起人目标的权限。 |
| 上述反演及 `e4848c6b-a008-5ae5-a2d3-37eacdea59e0` 报告任务 | zsh 报 `can't create temp file for here document: no such file or directory`。已有 `.tmp` 与 TMPDIR，但 zsh 的 TMPPREFIX 独立于 TMPDIR，默认临时前缀落在沙箱不可写的系统路径。报告任务后来正常完成并交付五个文件，不能把中间命令报错说成整个任务失败。 | Ask 隔离执行将 TMPPREFIX 指向本任务 `.tmp/zsh`；不扩大原文件或网络权限，Full access 逻辑保持原状。 |

原反演任务还包含计算时长需求、求解收敛问题及用户取消；本轮没有重跑科研求解，也没有将这些业务约束记为已修复的软件错误。

## 自动回归与真实沙箱

Linux 构建和测试全部在 Lakota，复用现有远端 target；本轮没有在本机运行 Rust 构建或清理已有缓存。最终完整回归 **175 通过、0 失败、2 项既有忽略**。新增覆盖无文件/无匹配候选经实际跨成员接收进入审核，以及拒绝 chat/revise/reopen 后任务状态、版本和运行授权不变；执行器夹具检查 TMPPREFIX，并在可用时调用真实 zsh。模拟审核和夹具不算真实模型证据。

`cargo fmt --all`、`cargo clippy --locked --offline --all-targets --target x86_64-unknown-linux-musl -- -D warnings -A deprecated` 通过。deprecated 例外为既有 musl libc::time_t 警告。107 份源码、测试、技能及 Cargo/build 文件的 SHA-256 与本机逐项一致；排除传输生成的三份 AppleDouble 元数据。未进行本轮 macOS 构建或 CI，不把本地未提交源码称为 CI 已验证。

单独在实际 Codex 沙箱做环境对照：未设 TMPPREFIX 时 zsh here-document 返回 1 并重现同一错误；设置为获准目录内前缀后返回 0，输出 `archive-probe 83`。两次均另有 Codex 清理历史 arg0 临时目录的警告，该警告未被本修复解决，也未清理用户临时目录。

## 最终源码的真实终端验收

同一 Lakota 上启动两个隔离成员 A/B 的实际交互 PTY、独立 localhost 信箱，使用真实 DeepSeek 与官方 Codex 0.162.1。两端保持 Ask for approval；新任务、确认、授权、补充输入和结束草稿均在终端操作。没有通过 SQL 写入任务结果或人工代做计算。测试后台在完成后停止，日常后台未停止或替换。

1. **能力问答**：`3c5ce890-72c4-5701-a409-e2cd802d80aa` 第 1 版。A 请求说明能力和批准边界，明确不要读项目文件。B 一次成功运行、一次读取任务、一次有效提交，`files:[]`；无原生命令、无快照、无 analyze、无附件。两端 completed，A 实际终端显示有意义的最终能力答复。
2. **隔离写入与被拒绝的补充要求**：`8485210c-4080-559a-9c31-11ab662addf7` 第 1 版。A 请求先等 12 秒，再用 zsh here-document 写两行 proof.txt、读回和求和；明确不自行设置 TMPDIR/TMPPREFIX、不联网或发送附件。B 在实际授权表单批准独立目录。确认 Codex 正在运行后，在 B 输入“请再增加一张示意图。”，终端准确提示应由发起人修改目标，但仍显示原任务处理中。随后同一次 Codex 正常结束，两端终端均显示已完成与准确最终答复。

写入任务实际命令返回 0，输出 `alpha=37`、`beta=46`、`sum=83`、`elapsed_seconds=12`；独立读取产物核对为 17 字节，SHA-256 `35743c526451fce250ca1fc96e374f9e62d28d91eb4bcf952ce722fd793a8b72`。没有新增示意图；两个任务均零 task_attention、零失败执行、零附件传输。两端测试原文件和白名单外测试文本均未改变。最终答复明确依据来自执行方记录，没有将发起方说成已直接查看执行方目录。

## 尚未解决的日志与证据位置

日常日志有持续的 `presence_unavailable`，也有历史附件 HTTP 502。源码会把心跳请求的发送错误折叠为此文本，原日志不足以分辨超时、连接或 DNS 原因；主消息同步可以成功而心跳失败。隔离验收期间也出现偶发同步超时和心跳过期，既有重试和一次手动 `/reconnect` 后恢复，没有重复执行任务。本轮没有修改网络代码或证明基础设施根因，不能声称所有错误日志已清零。

日常任务原始导出保存在 Lakota `~/xxassxx-tests/debug-chat-20261014/`；含模型输出，不纳入公开仓库。最终 PTY 文本/单元格/ANSI、测试日志、沙箱对照、只读证据导出在该目录及本机 `smoke-output/chat-errors-20261014/`。没有复制日常数据库、模型密钥或测试凭据进仓库。可提交的概要见 [精简证据](chat-errors-evidence.json)。
