# 成员收件箱：接口、终端与迁移

更新：2026-10-13（America/Denver）。收件箱随本地安装批次 `0.6.0-alpha` 部署到本机 owner、Lakota test 与 Trader 信箱，尚未公开发布。真实 dot 已在隔离团队完成连接、读取、回复与令牌刷新，见 [连接说明](dot-connection.md) 与 [验收记录](inbox-validation.md)。

## 终端操作

输入 `/inbox` 打开成员自己的持久收件箱；顶部显示未读线程数。Tab 切换全部、未读、需要我处理，方向键选择，Enter 查看。`n` 选择联系人、填写主题和正文，CtrlS 提交普通留言；`o` 查看本地发送状态。

详情中方向键选择前后原条目，PgUp/PgDn 滚动正文；`r` 回复当前条目的对方，`t` 打开关联任务。`m` 明确将当前及之前的内容标为本人已查看。后台抓取、打开列表、dot 阅读、回复、任务执行都不会代替这个动作。查看不会清除任务责任。正式问题仍在原任务回答；运行授权仍由执行成员在本机逐任务、逐版本开放。

断线时显示缓存和上次同步时间，留言及阅览游标分别保存在本地。恢复连接后重试相同幂等键。只有服务器已保存才显示“已进入对方收件箱”；后台同步回执只表示对方设备已保存，不表示本人理解或同意。旧客户端不能接收此类普通留言，需要新版终端或 dot。永久拒绝的发送项显示“需要检查”，当前版本未提供对其重新编辑的专用表单。

附件保留文件名、大小、SHA-256、来源和上传／可领取／已收件／撤销／清理记录；缓存中的当前状态以同步时间为准，本机也会检查已知过期时间。领取正文仍通过 CtrlF 或原任务，MCP 不提供正文下载。对方离线时未知的新本地进展不会出现在服务器。

## 数据与权限

个人 schema 10：`member_inbox_*` 保存线程、条目、单调变更游标、发送 outbox、明确阅览的待提交游标，以及只向本人展示的任务责任事实。单批条目和游标同一事务提交；重复同步不会生成任务或重复消息。

信箱 schema 2：`inbox_threads`、`inbox_entries`、`inbox_member_state`（同时记录参与关系）、`inbox_actor_receipts`、`inbox_changes`、`inbox_writes`、`inbox_sync_receipts`、`inbox_private_facts`。原有任务消息和新收件箱投影在同一事务提交。附件清单和状态也写入同一业务层。普通留言不进入 `relay_messages` 和任务执行路径。

任务按 task_id 聚合，但逐条按原始 sender/recipient 过滤。列表标题、最近条目、任务修订、未读、分页、附件元数据和回复目标都使用相同权限。A/B 与 B/C 同属一个任务时，A 不获得 B/C 内容。回复只回目标条目的对方。私有任务责任由自己的个人端上传最小事实，附修订和递增序号；旧版本不能覆盖新版。原始个人对话、模型推理、绝对目录与凭据不被该投影自动上传。

幂等范围为成员 + 幂等键：同内容返回原持久化结果，不同内容冲突。委托入口来自已鉴权上下文，不接受工具参数伪造发送者。每成员每分钟最多 60 条普通留言，主题最多 320 字节、正文 16384 字节、幂等键 128 字节。HTTP/MCP 请求上限 64 KiB，读取每页 1–100 条并限制约 2 MiB（首条保留）；服务端变更流单调递增。没有自动正文清理或主动提醒。

## 设备 HTTP 接口

新增接口仍使用设备凭据，仅限个人后台；不要将其交给 dot。

| 接口 | 作用 |
| --- | --- |
| GET `/v2/member-inbox?filter=all&before=0&limit=50` | 可见线程列表；filter 为 all/unread/action，next_before 继续分页 |
| GET `/v2/member-inbox/threads/{id}?after=0&limit=50` | 原始条目、可见任务修订和本人责任事实；next_after/has_more 继续分页 |
| POST `/v2/member-inbox/messages` | recipient、subject、body、idempotency_key |
| POST `/v2/member-inbox/threads/{id}/reply` | reply_to、body、idempotency_key；返回 current_revision |
| GET `/v2/member-inbox/changes?after=0&limit=50` | 成员专属条目及阅览／责任／回执变化，next_cursor/has_more |
| POST `/v2/member-inbox/synced` | through_seq 为已在本机提交的全局变更游标；仅后台保存回执 |
| POST `/v2/member-inbox/threads/{id}/viewed` | through_seq 为明确确认的可见线程序号；单调合并 |
| POST `/v2/member-inbox/threads/{id}/facts` | 本人私有任务责任事实：revision、sequence、state、needs_action、next_owner、action |

401 未认证，403 权限不足，404 不存在或不可见，409 幂等冲突，429 限流，400/422 参数错误，503 暂不可用。未知存储错误不返回正文、令牌或内部 SQL。`/v1/whoami` 新增 member_inbox_protocol=1；旧 HTTP 和文件传输接口保留。新个人端遇到旧信箱时显示暂不支持，旧任务仍按既有流程工作。

## 增量迁移与回退

本次源码与手动安装批次为 `0.6.0-alpha`，尚未公开发布。当前自动更新器只支持同 schema 更新，因此本次必须走管理员停服迁移。

1. 记录三端实际二进制哈希、个人 schema、信箱 schema、身份、目录白名单、授权和运行任务。等待在途工作结束；正常停止信箱、个人后台和所有 TUI，避免新旧二进制并行。
2. 为数据库及配置建立可恢复副本，连同必要文件存储保存在受限目录；停服后再复制，或使用 SQLite 在线备份 API，不能仅复制运行中的主数据库而漏掉 WAL。保留与旧 schema 匹配的旧二进制，核对备份可读。
3. 先升级服务器：新程序增量迁移信箱 1→2，回填既有持久消息及附件清单；历史阅览状态未知，作为启用前基线而非大量新未读。任务调度迁移不再将新 user_version 改回 1。检查完整性、成员、旧任务及文件接口。
4. 再升级试用个人端：个人库 9→10 保留身份、配置、白名单、任务、授权和对话，增加缓存与 outbox。连接信箱后检查 `/inbox`，待本地任务事实同步后核对历史未解决待办。缺少事实显示“状态待同步”，不猜测已解决。
5. 在隔离数据中完成 OAuth/dot 的授权、刷新、撤销和成员隔离后，再接真实协作内容，最后推广其他个人端。
6. 回退必须停服并恢复完整的、与旧二进制匹配的数据库／配置／必要文件副本。直接换回旧二进制不构成回退；迁移后新增内容须另行保留，不能无声丢弃。

每次部署记录数据库大小、迁移前后数量、同步失败、实际恢复能力及未验证项。本轮已获用户授权迁移上述现用三端；每台机器的可恢复副本位于 `~/.local/share/xxassxx/backups/inbox-060-20261013/`。真实 dot 连接仍限隔离团队，未扩大到日常数据。
