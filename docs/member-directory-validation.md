# 团队成员目录同步验收

日期：2026-10-08（America/Denver）。当前改动未提交、推送或发布；Trader、MBA、Lakota 已安装补丁构建，版本字符串仍为 `0.3.2-alpha`。

## 原因与实现

服务器已有 `relay_members(id,name,token_hash)` 持久表，由管理员配置在信箱启动时登记。缺陷在于该名单没有同步到个人端：联系人只在导入邀请/配置时写入，心跳又跳过本地名单外的成员，因此新加入的人不会自动出现在老客户端。

复用现有服务器表，`GET /v1/whoami` 在已鉴权的身份答复中新增 `member_directory: {protocol:1,members:[...]}`，只返回每人的 ID 和显示名，不返回凭据、凭据哈希或本地资料。目录包括尚未发送心跳的人；在线状态仍独立计算，不将“在团队里”当作“在线”。

客户端每轮信箱同步（现用后台正常轮询间隔 2 秒，另加网络耗时）验证团队与自身身份后，先验证整个目录，再原子更新联系人、配置中的联系人缓存和自身显示名，之后才处理消息。避免新成员的第一封消息被旧联系人校验挡住。仅更新目标字段，模型、执行、凭据设置和目录/任务/导出授权不变；已有会话、任务和消息不因名单调整删除。

旧信箱没有该字段时继续使用本地缓存；断网、格式无效、成员重复、缺少自身身份或团队不符时不覆盖上次有效名单。旧客户端可以继续连接新信箱，但不具备自动学习成员的逻辑，必须更新客户端。邀请文件和 `member.toml` 中的初始名单无需重写，运行时数据库缓存为当前来源。

TUI 周期刷新后会更新侧边栏、成员状态和 `@` 候选。以成员 ID 保持当前选择，避免名单插入后数字索引指向另一人；正在选择附件收件人而该成员消失时，返回附件列表要求重新选择。

本轮没有新增自助注册、公开用户查询接口或管理员增删命令。当前管理员仍管理 `server.toml`、凭据及邀请，并重新加载信箱使配置生效；现有九人成员上限不变。
