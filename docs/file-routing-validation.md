# 文件发送路由与 DeepSeek 验证

日期：2026-10-14（America/Denver）。源码版本 `0.7.2-alpha`；发布与部署状态以 `current-state.md` 为准。

## 实际故障

Trader 收到的任务把发起人 Mac 上的 ZIP 当成了需要 Trader 查找的材料。`@成员` 在调用本人对话模型之前就创建远端任务，因此模型没有机会选用已有的本机附件发送工具。执行方请求补充文件时，描述中未绑定的绝对路径又被消息校验拒绝。任务已被本人停止、归档，本轮不重开它，也不把另一批附件算作原任务完成。

后续人工发送的另一批两个 ZIP 在 Trader 均为 received；独立读取落地文件核对大小（204665、210216 字节）与清单 SHA-256 一致。原始路径、文件名及详细日志只保存在私有验收目录。

## 修复

- 普通对话先由本机助手判断文件归属与发送方向，`@成员` 仅指定对方。明确的 `create_task` 操作与已有任务接续仍走任务协调器。
- 工具说明与提示词一致区分本机推送、远端取件和能力提问；Full access 使用本机既有授权，Ask for approval 等待清单批准。本机路径支持绝对路径、工作目录相对路径、`~/` 和 `file://`。
- 对已存在的附件使用实时状态卡，隐藏“正在准备／请允许发送”的旧操作提示；原始历史保留。
- 未绑定路径以 `unbound://absolute` 等非授权位置引用传输，既有 `member://` 绑定、URL、普通斜线文字和本机原始历史保留。不把未知机器的路径归给发起人，也不将位置引用当成权限。
- CtrlY 使用任务列表的高亮行，避免提交没有任务编号的重试。
- 执行方显式重试后，发起方同步恢复处理状态；普通进度不能清除其他成员的问题或决定。
- 反向取件实测发现 standalone Codex 在 `.codex` 下时，Linux 的父目录拒绝会阻止它启动沙箱辅助程序。单独开放子文件仍会失败；最终方案在私有目录外缓存校验过的程序包，保留主程序、工具宿主与资源的配套目录结构，继续拒绝身份与历史目录。缓存不复制凭据。

## 分层证据

确定性回归覆盖本机／对方会话的附件发送、两种授权模式、咨询不创建任务、远端请求经过路由后才建任务、实时附件卡、未绑定路径的传输与重复转换、URL 保留，以及任务列表重试与恢复状态传播。Linux 程序缓存回归检查内容一致、复用、篡改拒绝、非 ELF 拒绝、配套程序完整和凭据排除。Lakota 最终源码完整回归 180 通过、0 失败、3 忽略（含新增真实 API opt-in），格式、Clippy 与优化构建通过；Clippy 仅沿用 libc 既有 deprecated 警告豁免。108 份构建输入与本机逐字节一致。

真实 DeepSeek `deepseek-flash`、thinking=false 的独立评估共 24 个输入（12 种表达 × 2 种权限模式），本轮全部选择预期工具。包括中文／空格／云盘式路径、相对路径、文件 URL、多个文件、远端取件、进展任务、能力咨询、引用示例和信息不足。评估不执行工具；另人工核对接收人和路径参数。它是本轮样本结果，不表示所有自由表达的答复措辞都已验证。

真实双 PTY 在 Lakota 的隔离成员 a 和 Trader 的隔离成员 b 之间，通过独立信箱与 SSH 转发的 TCP 连接传送合成文件；产品完成文件上传、下载与收件回执，未用 SCP 代替传输。日常成员、现有项目及实际团队信箱未用于该隔离实验。

1. 自然语言发送带中文和空格的 ZIP：a 在 Ask for approval 下停在 174 字节清单；真实终端按 a 批准后，两端分别显示送达和已保存，实际落地 SHA-256 匹配。
2. a 切到 Full access 后，以工作目录相对文件名请求发送 65792 字节二进制，自动送达且哈希一致。
3. b 通过 CtrlF → n → 收件人 → 文件选择器 → CtrlS 反向发送，同样送达。
4. 修复后的终端以文件 URL 再次请求发送，得到实际送达状态，旧批准提示已不再显示。
5. 远端取件首次被 standalone Codex 沙箱启动问题阻断；保留失败记录，通过真实任务列表 CtrlY 续接同一任务。最终程序包缓存修复后，Codex 找到 b 工作目录的 ZIP，b 的 Ask 清单批准后，a 收到文件并完成结果审核。两端实际终端均显示已完成和有明确文件来源的最终答复。5 批文件的两端落地大小、SHA-256 与对应源文件一致。

最终只读沙箱独立探针验证：程序和允许目录可读，合成的私有目录标记不可读，工作目录不可写。真实终端使用最终源码的去符号 debug 构建，缓存哈希较慢；优化发布构建另行通过，不将 debug 耗时当成生产性能。任务编号、二进制哈希与精简结果见 [证据](file-routing-evidence.json)。

原始终端、模型决策、构建日志和合成测试数据保存在 Git 忽略的 `smoke-output/file-routing-20261014/` 及两端同名测试目录。
