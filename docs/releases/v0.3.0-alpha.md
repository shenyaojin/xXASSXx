# 0.3.0 Alpha：实际文件与结果交付

本版让成员直接交换实际文件，并把文件接收状态接入任务完成判断。

## 新增

- CtrlF 选择成员和文件、发送、接收、另存为、打开与继续只读分析。
- 现有文件先由执行方查找，再由文件所有者允许导出。任务产生的结果也可以单独授权发送；目录读取白名单不等于导出授权。
- 固定文件副本、SHA-256 校验、分块续传、离线暂存与接收回执。任务要求交付文件时，文件完整收到后才完成。
- 默认单文件 1 GiB、每批最多 40 文件/2 GiB，20 MiB 以下批次自动接收；额度与保留期可配置。
- 附件能力单独协商，不把新附件任务派给尚未支持的客户端。

## 修复

- local agent 的任务决策按阶段约束并校验，异常动作有界重试，不把错误响应当成功。
- 纯文件交付的最终答复依据真实接收状态，避免复用下载前的说明。
- 重开任务按版本分别归档，保留旧结果，避免第二次完成导致后台退出。
- 附件输入、工作目录展示及文件选择界面的操作提示。

## 安装与升级

提供 Apple Silicon macOS、Intel macOS、Linux x86_64 三个平台安装包，附带 `SHA256SUMS` 和 `install.sh`。

```sh
sh install.sh --version v0.3.0-alpha
xxassxx --version
```

先升级团队信箱，再升级各个人端。升级前等待在途任务结束，运行 `xxassxx client stop` 并退出旧界面；安装后重新打开。个人数据库增量迁移至 schema 9，保留身份、配置、白名单与历史。无需重新初始化或导入邀请，迁移后的数据库不能用旧版程序打开。

## 验证与边界

发布前 127 项默认测试、格式检查与 Clippy 通过，另有两项旧 opt-in 测试默认忽略。真实终端验证了 Mac 与 Lakota 双向传 CSV/PNG、执行任务生成文件后交付、附件继续只读分析，以及手动下载前后任务状态的变化；隔离测试记录见 [附件验收](../file-transfer-validation.md)。这不代表真实 1 GiB 传输、七天保留周期或大规模负载已经验收。

信箱暂存文件内容，本版没有端到端加密或目录实时同步。继续处理快捷入口是只读分析；修改/运行收到的文件需先另存，再走独立任务授权。未知本地路径的查找与发送仍是两步操作。成员目录自动同步尚未包含。

详见 [操作说明](../file-transfer.md)。
