# 团队动态与在线协作

2026-10-15。0.9.0-alpha 开发版；验收与部署状态以 `current-state.md` 为准。

输入 `/activity` 查看团队共享任务列表，Enter 打开完整记录，↑↓ / PgUp / PgDn 滚动，Esc 返回。记录显示任务目标、发起人、执行成员、版本、处理阶段、最终答复、来源文件及可用的内容哈希、下一步责任。非参与成员也可以查看；查看不会创建任务、运行程序、批准文件发送或清除私人收件箱的未读。

新的任务由执行端实际绑定白名单后开始共享。只读查询、目录定位和选文件使用执行端显式登记的白名单；工作目录在白名单之外时，以第一个白名单作为起点，仍可跨多个白名单查找。Full access 不把系统根目录自动变成团队查询区。写入/运行任务的起始工作目录在白名单内时，也公开任务进展和结果；执行范围仍由本机 Ask for approval / Full access 决定，因此该任务的最终交付内容应按团队可见准备。白名单外的通用执行、独立附件分析及私人留言不自动成为共享记录。

任务公开的是目标、处理状态、最终答复和选定的来源依据，不是目录全部内容，也不监控文件的每次修改。原始工具日志、模型内部记录、私人问题正文和凭据不复制到团队动态。源文件仍由原成员保管；其他成员要原文件，另行通过既有任务与文件传输流程获取。旧任务不会因升级而追溯公开。已发布的记录作为协作历史保留，移除白名单会停止其后续读取，不能撤回其他成员已经看到的内容。

新任务派发要求执行端有 30 秒内的有效心跳，并运行支持团队动态的客户端。未满足时，本机保留尚未派发的请求并显示等待，待执行端上线后继续；不能把信箱已收到等同于开始执行。已经接收的任务、最终结果和交付收据保留基本断线恢复与去重，不做文件副本、分支或合并。动态页同时标注最近同步时间和成员在线状态；过期缓存不能证明机器仍在执行。人不必坐在终端前，客户端后台在线即可。

实现使用原有经鉴权的任务事件流，信箱在任务角色与版本检查后生成独立的共享投影。所有当前团队成员可以分页读取 `/v2/team-activity?after=<cursor>`，撤销成员后不能继续请求；历史已下载副本不会远程删除。客户端按游标保存投影，旁观成员不会收到执行消息。原 `/inbox` 及 MCP 的双人可见范围保持原语义；MCP 尚未增加团队动态入口。

个人数据库 10 → 11，信箱 2 → 3，均为增量迁移，个人旧任务的共享标记默认为关闭。需要备份并升级信箱与客户端；现有更新器不自动跨 schema 升级。旧客户端不能执行要求团队共享的新任务，但已有旧任务结果仍正常送达。版本升级本身不改变本机访问模式。

## 手动进入 Codex

`/codex` 先显示本机白名单目录与其中的当前工作目录。↑↓ 选择后 Enter 启动，也可按 p 输入白名单内的子目录。启动前重新校验真实路径与当前白名单；取消不会启动进程，目录失效或 Codex 不可用会回到 xxassxx 显示原因。

这会把当前终端交给用户直接操作的 Codex。退出 Codex 后恢复同一个 xxassxx 会话，后台协作继续运行。这里使用 Codex 自身的交互权限、登录和设置，不偷偷附加后台的自动批准参数；白名单在此规定可选的启动目录，不声称工作目录本身是 Codex 的文件系统沙箱。手动会话不自动加入团队任务或发布其内容。后台 agent → Codex 的交接流程不要求人选择目录，继续使用已有任务绑定。
