# 附件功能验收

日期：2026-10-07（America/Denver）。本轮为源码实现及隔离测试，没有安装到日常使用的三个服务，也没有提交、推送或发布分发包。精简结构化证据见 [file-transfer-evidence.json](file-transfer-evidence.json)。

## 确定性验证

完整 `cargo test --offline`：127 项通过，0 失败，2 项旧 opt-in 测试维持默认忽略。`cargo clippy --offline --all-targets -- -D warnings` 通过；Mac debug 与 Lakota Linux release 构建通过。

附件回归验证了：授权前不发送、固定副本与原文件后续修改无关、接收回执、另存为不覆盖、未授权成员拒绝访问、块重复提交幂等与内容冲突、撤销、即时过期、符号链接/应用私有状态/超限文件拒绝、只读附件分析的独立范围、任务完成所需成员/版本/清单/接收状态一致性，以及历史超过列表显示数量时仍推进老传输。另有附件任务等待接收端能力注册并自动继续的兼容测试。

恢复测试使用 40 MiB + 7 字节实际文件，在部分上传、部分下载时分别重启隔离信箱，验证续传后的字节一致。未运行真实 1 GiB/2 GiB 边界文件、磁盘实际写满、七天真实等待或长时间断网测试；大小限制与即时到期检查不能替代这些长时压力测试。服务端磁盘清理为周期任务，本轮没有用真实等待周期证明全部保留期组合。

验收结束后已停止本轮独立个人端、信箱和 SSH 隧道，保留所有测试文件、数据库及终端记录；日常使用的三端未改动。

原始日志：`smoke-output/file-transfer-final-tests.log`、`smoke-output/file-transfer-clippy.log`、`smoke-output/file-transfer-linux-build.log`。回归的模拟模型/执行器证据与下列真实模型证据分开。

## 真实终端与模型：同机隔离双端

目录：`smoke-output/file-transfer-real-f994327d/`。使用真实 PTY 启动 xXASSXx，逐步按键操作并采集 ANSI 与屏幕文本；没有控制用户已经打开的原生窗口。

1. A 的 CtrlF 文件选择器选择 `pressure.csv` 和 `pressure.png`，CtrlS 发送；两端分别显示已保存到对方电脑、已保存到本机。文件 SHA-256 一致。
2. B 在附件详情选择 CSV，按 c 说明求最小值、最大值和均值，CtrlT/CtrlS 确认任务 `8491b62c-2057-5820-9d6b-dd2346dd7f79`。官方 Codex 实际读取限定副本，DeepSeek 整理后，最终终端答复为最小 10、最大 30、均值 20，共三条合成数据，单位未知。永久白名单未扩大。
3. A 发起 `c04aa587-0311-54f3-851b-0d0e814a8209`，要求生成 CSV、报告、真实运行均值核对，并发送两个实际文件。B 终端开放本任务独立目录，单独勾选允许交付结果附件。真实 Codex 生成 `values.csv`（2、4、6）和 `report.txt`，实际运行 awk 校验均值 4；首次 Python 因缺少本机开发工具失败，日志保留，成功依据来自后续真实 awk 输出。A 实际收到 12 字节 CSV 与 1388 字节报告后显示已完成，最终答复忠实说明了失败尝试与最终结果。

实测发现并修复：附件输入面板遗漏粘贴/渲染；新 `deliver_files` 布尔类型未被通用决策校验器接受；附件后续分析的实际工作目录展示不正确。失败记录保留，通过正常恢复和重新操作复验，没有修改业务数据库伪造成功。

## 跨机器：Mac 与 Lakota

目录：`smoke-output/file-transfer-cross-56d2e303/`；远端为独立 `xxassxx-tests/file-transfer-e683d0f0/acceptance/`。

使用真实鉴权 Rust 信箱，经 SSH 反向隧道连接 Mac 与 Lakota。传输跨越真实两台机器，终端 B 通过 SSH PTY 实际运行 Linux 版本。没有部署现用 Trader HTTPS 服务，不能把这轮证据写成三端现用版本升级验收。

- Lakota 通过 CtrlF 发送 `lakota.csv`；Mac 显示收到，Lakota 显示对方已保存。
- Mac 发送 CSV 与 PNG，Lakota 显示收到；后续再次使用终端文件选择器发送成功。首次两次复制检查检测到源文件元数据变化，未生成获准发送批次；保留错误并重新选择。中间另有一次命令行发送用于复查，同样记录在证据里，不把它冒充终端操作。
- 任务 `eecc92a9-f54f-5484-b9d8-b4f750b81a52`：Mac 自然语言请求 Lakota 原始 CSV；真实 DeepSeek 和官方 Codex 在 Lakota 查找原文件，B 的 CtrlF 显示等待允许发送，按 a 批准。Mac 将自动接收阈值设为 0，实际看到业务任务保持等待，确认文件后按 d 下载才完成。
- 第 1 版暴露“最终答复复用下载前审阅文字”的问题。修复为纯文件任务直接依据完整接收与校验记录生成最终答复。通过 CtrlE 重开同一任务第 2 版，重新确认、对方批准、手动下载复验。各版本仅一次文件发现执行；等待下载不重复运行 Codex。

另发现旧结果归档仅按任务编号命名，任务重开后的第二版会触发不一致检查并停止后台。已改为每个任务版本分别归档，保留旧文件，补充重开归档回归；更新隔离双方后二版完成事件正常同步，没有重跑发现任务。

两端文件内容由独立只读脚本重新计算 SHA-256，与发送清单逐一比较。终端记录包括等待下载、收到文件和最终答复，数据库只作核对。结构化证据记录最终两端二进制 hash 与后台状态；较早运行版本的证据另存于跨机器测试目录的 `evidence-before-archive-fix.json`，初始构建信息见 `setup.json`。归档修复后的重启仅继续已有完成通知，没有新运行 Codex。

## 当前边界

- 文件交付与接收可用，附件后续快捷入口目前是单个文件的只读分析。写入/运行须先另存再走独立任务授权。
- 未知本地路径不会在一句话内自动完成查找、选择与发送；先查找或使用文件选择器。尚无附件专用 MCP 工具。
- 打开文件使用系统关联程序；本轮核验了保存文件和只读分析，没有逐一测试所有桌面文档应用。
- 信箱可读字节，没有端到端加密。本机副本不会随信箱清理自动删除。
- 同机和跨机器都是小型合成测试资料，不构成科研结果或大规模传输的业务验收。
