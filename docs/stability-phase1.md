# 稳定性第一阶段：恢复原任务与可追踪输入

日期：2026-10-16（America/Denver）。本阶段为 0.9.0-alpha 候选改动，不是发布或日常客户端升级。精确源码、二进制、任务和验收状态见 [精简证据](stability-phase1-evidence.json)。

2026-10-21 更新：下文保留本阶段历史。现行 `CtrlY` / `/recover` 已改为处理菜单，默认打开补充，按 `r` 才明确续接；补充默认仅保存，按 Tab 可选择保存并续接。执行方也能在原任务保存本机约束，材料拒绝会反馈逐项原因与可用材料。当前行为、安装与验收见 [可处理恢复记录](actionable-recovery-validation.md)。

## 产品入口

- `/answer`（原 CtrlB 保留）：选择具体待答问题，保存用户原话及问题、任务、版本绑定。询问状态不会解除等待，一个答案不会解除其他问题。
- `/supplement`：补充或纠正当前任务，不需要模型先正确识别自然语言意图。分别显示本机保存、执行方接收、执行读取；读取仍不代表采用或完成。目标或执行成员改变仍使用现有修订流程。
- `/recover`（CtrlY）：先展示失败原因、责任人和要恢复的步骤，再按 Enter 允许有限继续。绑定打开页面时的任务版本和失败步骤，防止在后台状态改变后恢复错误步骤。详细记录保留原始错误。

补充不会解除取消、权限等待、其他问题或技术阻塞。暂停于用户问题时必须回答对应问题；暂停于配置问题时应先修复配置，再明确恢复。授权仍由执行电脑本机主人作出；本阶段没有扩大旧批准或自动开启 Full access。

## 实现与边界

`task_recovery::Reason` 是小型恢复合同，包含临时模型/网络故障、认证/额度/配置、用户事实/决定、本机权限、执行不确定、预算耗尽和无法自动修复的执行错误。`reason`、`action`、责任人及具体 job/execution 驱动恢复，不解析中文错误文案。已有问题表和本机权限记录仍是相应等待的事实来源。

任务准备、问题处理、结果审核及符合条件的只读执行采用持久化 `retry_at` 与有限上限：2、4、8……秒退避，单次最多 120 秒。HTTP 408/500/502/503/504、超时及连接错误属于临时故障；认证、额度等问题需要处理。重启后继续读取原计划；取消、版本变化和授权校验仍优先。模型的成功返回必须经过现有验证和提交边界；故障代理只注入 HTTP 错误，成功响应来自真实服务。普通自由聊天分类不属于新的持久任务重试 job；确定性入口可独立使用。

可能已有副作用的执行不会因连接故障自动重放。中断记录保留，由用户通过产品恢复；执行上下文携带旧运行、原错误和检查/复用要求，并续接原 Codex 会话。成功的物理运行保留，只重试失败的审核或后处理步骤。该机制不声称提供外部系统的通用“恰好一次”事务：无法确认外部副作用时执行助手应提问，不能猜测后重做。

`attempts`、`round` 和历史运行始终累计。自动预算与 `task_recovery_grants` 中用户明确新增的有限预算分开保存；job/执行重试上限从当前累计值增加，不清零旧计数。重复同一恢复请求幂等。新增预算耗尽后再次暂停，不会无限循环。

`task_inputs` 保存不可覆盖的原话、任务、版本、输入编号及可选问题编号；`task_input_receipts` 保存每位目标成员的接收/读取回执，`task_input_reads` 保留每次运行的消费记录。执行调用 `get_task` 时读取最新上下文并记回执；若提交前出现未读取的新输入，内核拒绝旧上下文的提交，要求重新读取。结果候选携带读取的输入编号；不能把消息送达等同于结果已经采用。原始业务文件是否读取和采用，仍由实际命令、文件哈希及交付结果核验。

## 自动回归与实机证据的分界

自动回归覆盖重复输入/回执、过期版本、多个待答问题、状态询问、取消、授权撤销、重试上限、重启读取退避计划、有限预算耗尽、远端恢复和仅重试审核。模拟模型与临时测试数据库用于验证边界，不作为真实模型或跨机交付证据。

实机使用 Lakota 的隔离成员 a、Trader 的隔离成员 b、独立实际信箱、真实 DeepSeek local agent、官方 Codex 和两端实际 PTY。两端保持 Ask for approval，由产品界面批准每项合成任务。开发者只创建测试输入、注入故障、操作终端并只读核验；没有替执行 agent 计算、发送成果或修改任务数据库。

原始画面、ANSI、故障记录、模型代理元数据、执行事件和只读核验快照放在 Git 忽略目录 `smoke-output/stability-phase1-20261015/`；远端原始目录均为 `~/xxassxx-tests/stability-phase1-20261015/`。配置、令牌和凭据不入库。A–F 的实际结果与路径由精简证据逐项列出。

## 下一阶段接口与迁移

个人库 schema 12 → 13 为增量迁移：新增五张输入/恢复表、`app_tasks.recovery_protocol`、job 退避/上限字段、execution 退避/累计尝试字段。旧任务 `recovery_protocol=0`，不追溯启用新的自动恢复；原授权范围与记录保留。信箱 schema 没有变化。

任务通信仍为 task_v2，新增 `input`、`input_receipt` 事件，候选增加 `input_ids`，暂停进展增加 `blocker`。新任务声明 `recovery_protocol=1`。两端使用本阶段候选才能完整提供执行读取回执；不能把混用旧客户端的收件记录当作消费证据。下一阶段若继续演进角色和协议协商，应保留这些版本/输入/步骤标识和幂等边界。

API 延续 `answer_question`、`retry_task`，新增 `supplement_task`；恢复可带 `block_id` 防止过期界面操作。恢复赠予预算不修改设备访问模式。迁移前仍需遵循现有停服和备份要求；本阶段未安装到日常数据目录。
