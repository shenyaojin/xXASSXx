# 访问模式与手动重连

更新：2026-10-15。下述简化行为用于 0.9.0 候选源码，日常 0.8.0 尚未升级；本轮验收状态以接续摘要为准。客户端入口为 `/access`，仅提供两种模式。底栏始终显示当前选择；设置只保存在本机，退出、重启后保留，不改变其他成员或全局 Codex 配置。

| 模式 | 行为 |
| --- | --- |
| Ask for approval（默认） | 执行方批准整项任务一次，即允许任务所需的本机文件读写、运行、联网、依赖安装、本机凭据生成/使用及指定成果发送。批准绑定当前任务与版本，交接 Codex、回答问题后续接不再重复批准。明确只读要求仍须遵守。单独取已有文件的请求保留发送清单批准。 |
| Full access | 本机 Codex 可以读写本机文件、运行程序及联网；清晰任务自动确认，本机承接的团队任务不再等待逐任务运行许可，所需文件自动发送。明确的只读要求仍须遵守，真正缺少的业务信息仍会询问。 |

例如 Mac 开启 Full access、Lakota 保持 Ask for approval，Lakota 仍会等待本地主人批准。只有 Lakota 自己开启 Full access 后，它承接的工作才免逐项批准。模式不能从聊天文字、对方消息或模型调用中设置；选择器会明确说明它也适用于团队交给本机的任务。文件内容与收件状态仍由原有固定副本、校验与回执机制处理。

新版批准面板列出完整范围；任务目录作为默认产物和日志位置，不再把任务要求的原文件修改、联网或依赖安装挡在外面。私钥与秘密在本机使用，不是可交付成果；明确索取的公钥可以作为文件发送。白名单仍用于公共资料查询和共享记录，加入白名单本身不等于批准写入任务。任务目标改变后的新版本需要新批准，单纯回答待处理问题不创建新版本。

个人数据库 schema 12 为执行授权增加完整任务范围标记，旧记录默认保持受限范围：独立目录可写、原文件只读、不联网。升级不会把历史批准或现有 Ask 设置自动变成 Full access。旧任务可由执行方在当前执行结束后重新打开 CtrlG，明确批准完整任务范围；仍需处理真实的待答问题，不自动重放失败或结果不确定的执行。

## 聊天回答与分阶段交付

当前任务提出问题后，可以直接在聊天中回答。模型识别回答针对的问题，内核校验发送时的问题和任务版本，保存用户原话并实际提交答案；解释、状态询问和含糊回复不会直接解除等待。多个问题需要明确对应关系，也可继续用 CtrlB 选择。一个问题的答案不会清除其他问题。

答复与任务卡区分“答案已提交，等待执行方接收”和“执行方已接收，正在准备续接”；执行仍由执行机器完成。活动任务的状态回复由实际持久状态生成，模型不能用一句“已继续”替代状态迁移。团队动态也区分提交和接收，附件进度不会解除业务等待。

需要用户完成外部操作时，可先交付阶段文件再等待，例如生成专用密钥、自动交付公钥 txt、询问公钥是否已加入 GitHub，收到聊天回答后再继续克隆。执行端 `submit_task_question` 可携带所请求阶段文件的 `deliveries`，使用与最终成果相同的固定副本、传输和收件校验；这不代表整项任务已完成。

正在执行的 Codex 运行必须先结束或停止，才能切换模式。切回 Ask 后，不再自动为未批准任务提供完整权限；已经明确批准的任务仍按该任务的有效授权执行。仅依赖 Full access、没有独立任务批准的未完成任务需要本机批准后继续。已经批准并开始的传输继续。自动模式不恢复已停止、失败或执行结果不确定的任务，也不取消真正的业务澄清。

Full access 按用户明确选择提供完整文件及网络能力，参考 [OpenAI 权限说明](https://learn.chatgpt.com/docs/permission-modes)。Ask for approval 是 xXASSXx 的逐任务批准，不是 Codex 交互终端的逐条命令批准界面。新版整项任务批准使用完整执行能力并遵循具体任务要求；旧版逐文件协作协议和历史受限批准不被自动扩大。

## 重连

输入 `/reconnect` 立即请求重试信箱连接。正在运行的后台会提前结束重试等待；后台未运行时启动它。不会为了重连重启活动执行，也不会重放已完成或结果不确定的任务。未送达的消息和文件仍沿原有持久队列同步。命令行对应 `xxassxx client reconnect`。

默认正常轮询间隔为 2 秒。临时断网、超时、限流和可重试的服务端错误会继续重试，失败等待约为 4、8、16、32、60 秒，最长 60 秒；实际还包含一次网络请求耗时。身份验证／凭据错误直接阻塞，其他不可重试故障达到默认 3 次后停止后台。手动重连可以重新尝试，但不会修复凭据或修改账户配置；仍失败时由 `/status` 查看原因。
