# 访问模式与手动重连

2026-10-13。客户端入口为 `/access`，仅提供两种模式。底栏始终显示当前选择；设置只保存在本机，退出、重启后保留，不改变其他成员或全局 Codex 配置。

| 模式 | 行为 |
| --- | --- |
| Ask for approval（默认） | 保留现有确认流程：通用任务确认目标，写入/运行需执行方允许独立任务目录，原文件只读且不联网；文件发送需批准清单或本任务成果范围。符合条件的明确取已有文件指令仍可直接开始只读查找。 |
| Full access | 本机 Codex 可以读写本机文件、运行程序及联网；清晰任务自动确认，本机承接的团队任务不再等待逐任务运行许可，所需文件自动发送。明确的只读要求仍须遵守，真正缺少的业务信息仍会询问。 |

例如 Mac 开启 Full access、Lakota 保持 Ask for approval，Lakota 仍会等待本地主人批准。只有 Lakota 自己开启 Full access 后，它承接的工作才免逐项批准。模式不能从聊天文字、对方消息或模型调用中设置；选择器会明确说明它也适用于团队交给本机的任务。文件内容与收件状态仍由原有固定副本、校验与回执机制处理。

正在执行的 Codex 运行必须先结束或停止，才能切换模式。切回后，新执行不再有完整权限；此前依赖完整范围且尚未完成的任务可能需要重新确认有效范围或重开版本。已经批准并开始的传输继续。自动模式不恢复已停止、失败或执行结果不确定的任务，也不取消真正的业务澄清。

Full access 按用户明确选择提供完整文件及网络能力，参考 [OpenAI 权限说明](https://learn.chatgpt.com/docs/permission-modes)。Ask for approval 沿用 xXASSXx 的独立任务目录与文件授权流程，并不声称其后台非交互执行器具有 Codex 交互终端的逐条命令批准界面。旧版逐文件协作协议不因新设置改变其授权合同。

## 重连

输入 `/reconnect` 立即请求重试信箱连接。正在运行的后台会提前结束重试等待；后台未运行时启动它。不会为了重连重启活动执行，也不会重放已完成或结果不确定的任务。未送达的消息和文件仍沿原有持久队列同步。命令行对应 `xxassxx client reconnect`。

默认正常轮询间隔为 2 秒。临时断网、超时、限流和可重试的服务端错误会继续重试，失败等待约为 4、8、16、32、60 秒，最长 60 秒；实际还包含一次网络请求耗时。身份验证／凭据错误直接阻塞，其他不可重试故障达到默认 3 次后停止后台。手动重连可以重新尝试，但不会修复凭据或修改账户配置；仍失败时由 `/status` 查看原因。

本轮验收及安装事实记录在 [访问模式验收](access-modes-validation.md)。
