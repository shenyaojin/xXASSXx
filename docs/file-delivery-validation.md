## 原因与修复

原任务 `defc0941-301a-51b9-a2e9-f8713c27939b` 第 3 版为 files 模式。Lakota 在发现阶段选了 15 份文本资料，原逻辑却把同一 `files` 字段直接作为导出附件。与此同时，给执行助手的通用发现合同仍要求“只选 UTF-8 文本，随后冻结给另一轮分析”，与支持二进制的文件交付路径冲突。该路径实际上没有后续文本分析轮次。因此，问题不只是模型说得太长，而是参考资料、待发附件和执行阶段的合同混用。

files 模式改为独立的只读文件选择合同：`files` 保存查阅依据，必需的 `deliveries` 单独保存交付文件。内核拒绝仅有参考资料的交付结果，不会回退成发送 `files`。保持相对路径、允许目录、真实文件及发送方逐批批准检查。支持原始二进制文件，优先已知项目位置和同任务旧版本的已接受查找结果，必要时只读少量依据，不将找最新文件扩大为重新验证项目。旧结果属于证据，不能扩大当前访问权限。

自动准备附件只记录文件批次说明，不再截取执行助手的查找长文作为附件备注。任务结果保留原说明。附件主界面固定显示收发成员、真实状态、文件名、大小与操作；长备注、错误和选中文件路径放在 i 详情。列表选择自动跟随，未开始传输时不显示逐文件 0 字节，浏览附件时隐藏对话输入框。发送方任务卡从本机实际传输状态显示“等待你允许发送文件”，不再把等批准显示为正在核对结果。完成答复直接指出收件人及文件名，避免共享到发送端后误称文件保存到“本机”。
