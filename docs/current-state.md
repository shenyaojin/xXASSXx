## 产品理念与第一批用户

开发者正在组建一家以人少而精为特点的创业公司，主业是地球物理相关的软件与服务。团队自己就是 xXASSXx 的第一批用户。xXASSXx 是为主业中的协作需求产生的副产品，先服务内部真实交付，成熟后可以考虑对外销售；当前没有把它确定为独立主营业务，也没有验证外部付费需求。

用户的长期判断是：由少数专业成员组成、每个人都有强大 agent 辅助的小团队会越来越普遍。这是指导产品的假设。xXASSXx 希望让这些成员各自的 agent 在授权范围内交换工作进展、文件与成果，把必要上下文交到下一位成员手里，减少人工催进度、转述、找文件和仅用于同步状态的会议。人的专业判断、客户沟通和关键决策仍需保留。

理解产品时，应从多位真实成员之间的工作衔接出发，覆盖研究、开发和服务交付，而不局限于同一代码仓库中的多个编程 agent。文件管理、脚本管理、消息和任务状态都服务于这个目标；不要仅把项目定位成文件搜索器、网盘、聊天工具或单人多 agent 调度框架。

### 什么是高品质沟通

一次有效交接应让接手者知道：

- 原始需求是什么，谁负责，当前进展和阻塞在哪里。
- 使用了哪一版数据、脚本和参数，相关材料在哪里、允许怎样访问。
- 产生了什么结果，依据是什么，哪些检查已完成，哪些结论仍不确定。
- 下一步需要谁做什么，以及哪些事项需要人来判断或确认。

例如，某成员完成一轮分析后，下一位成员的 agent 能取得获准访问的结果与必要上下文，明确版本和局限，再继续准备后续工作；相关成员可以了解进展而无需反复询问。这是目标体验，不表示已经实现自动连续交接；实际科研程序执行见下方既有部署记录，新增文件交付见本轮附件能力与发布记录。

## 产品与架构共识

- xXASSXx 面向小团队，Rust 内核，macOS/Linux，自己的终端界面；暂不考虑 Windows。
- local agent（旧称“管家”）收集意图、上下文和澄清，协调成员。大部分实质任务交给各成员自己的 Codex，使用 Codex 原生工具；不要在 Rust/local agent 中另造通用文件搜索、分析或代码执行工具链。
- 通信结构：Codex A ↔ local agent A ↔ HTTPS 团队信箱 ↔ local agent B ↔ Codex B。通过 local agent 联系另一人，不把其他人的 Codex 当成可 @ 的联系人。
- local agent 当前用 DeepSeek；预留 Ollama/兼容 API，但尚未验证真实本地模型。Codex 使用用户已有官方登录。
- MCP 提供任务上下文、结果提交与协作接口；持久后台负责唤醒、队列、执行和回传。
- 长期以成员本地保管资料、按任务需要授权访问为方向。中央信箱负责跨成员通信与协调，不以集中收走所有人的业务文件为前提。
- 当前实装范围：白名单内默认只读查找、查看、解释文件；另外支持执行方逐任务、逐版本开放独立目录后修改副本并运行程序。原文件和额外依赖只读，写权限不来自目录白名单。不是持续监控。
- 添加白名单允许 Codex 按本地或团队请求读取并返回答案和相对文件引用，不自动上传整个目录。普通找文件不要求 object ID 或预先导入。
- 原有固定快照与逐文件授权的协作流程保留，与目录白名单查询并存。不能把目录白名单路径说成每项团队查询都需要独立人工授权，也不能把原生查询的文件引用校验说成固定版本的读取证明。
- 本地保管不等于内容永不离开电脑：获准读取的文本可能进入模型上下文，回复会经过团队信箱。不要声称已有端到端加密或全部推理均在本地运行。
