## 用户操作

1. `xxassxx open PATH` 打开工作目录。CtrlP 选择或输入其他目录；CtrlR 单独管理可访问目录。拒绝加入白名单仍可聊天。
2. 在普通聊天输入 `@test 请找出适合……的入口脚本，并说明参数、差异与依据`。自己的 local agent 立即接住一张待确认任务卡，保留原话并整理目标。也可用 CtrlN 创建本地或协作任务。
3. CtrlT 进入任务，检查交付、参与者、限制与未知项；CtrlS 或输入明确的「确认」确认**当前修订**。确认前不联系参与方、不启动该任务的 Codex。CtrlE 修改，CtrlX 取消。
4. 问题需要本人补充时，CtrlT 选择任务，CtrlB 选择问题并输入答案。普通输入始终与助手对话；只有按 CtrlB 选中问题后，输入才作为该问题的答案。回答携带任务、修订和问题 ID，不会广播给其他任务。
5. 任务内的普通交流仍归属于同一任务。补充事实保留在当前修订；改变目标或加入参与人进入新修订，重新确认。Esc 解除任务关联，回到普通聊天。
6. A 检查交付齐全后自动完成并归档，无需再点人工验收。CtrlT 包含已归档任务；CtrlD 查看结果、修订、问题、材料来源、执行与会议记录。CtrlE 在原编号上重开。
7. CtrlO 的 `n` 新建独立对话，同一目录可以保留多段对话。CtrlQ 关闭界面，后台继续；重开界面能看到持久通知。

没有增加 slash 命令。CtrlG/CtrlU 的固定文件授权仅用于历史兼容；新流程在已有白名单内自动发现并固定材料。

确认、成员目录归属和 Linux 沙箱的后续通用修复见 [修复说明](task-confirmation-fix.md)。

## 实现结构与事实边界

`app_tasks` 是业务任务身份，UUID 用于协议，`T-xxxxxxxx` 仅用于显示。`task_revisions` 保存原话、草稿、参与者与确认记录；`task_journal` 保存消息和决策；问题、材料、模型尝试、执行分别有稳定关联。物理执行继续复用原来的 `tasks`、`runs`、租约、MCP 与官方 Codex runner。一次 MCP 提交、进程成功退出、业务任务完成分别记录。

`task_coordinator.rs` 在事务内处理确认、修订、问答、候选、完成和待发送消息。协议 `task_v2` 含版本、任务、修订及按发送者单调递增的序号；外层消息提供消息 ID、经过认证的成员及收发方向。重复副作用幂等；过期修订保留历史；同修订迟到进度不能覆盖较新事件。只有发起方 A 可以确定最终完成。信箱不运行第二个 LLM 决策者。

local agent 的决策是结构化数据，Rust 检查后才推进。B 先核对已知事实，无法回答再问 A；A 用已确认要求与已有聊天回答，仍缺用户选择才提问。调查与专业复核始终由当前任务的执行成员处理：有外部参与者时由这些成员执行，纯本地任务由发起人执行。A 需要补查时将要求发回原执行成员，不能因为模型选择 investigate 而改在 A 本机读文件。调查指令明确不是已知事实，结果须来自实际读取。它仍受当前目录、白名单、快照和轮数约束。目标/参与者变更另开修订；模型无权确认用户意图。

工作目录、可访问目录和会话分别存储。新任务保存所选逻辑目录，各成员绑定自己的根目录；入站 B 使用自己最近选择的工作位置，未选择时使用已有 executor.workdir。目录失效明确进入需要处理，绝不改用首个白名单目录。切换界面目录不修改已经绑定的任务。

后台收发、用户对话、执行使用不同连接；模型与网络等待不持有 SQLite 事务。每个执行及协调工作有独占锁。服务中断时，执行或模型结果不确定会停在需要处理；不会因为例会到来而自动重放。CtrlY 是显式恢复入口。恢复仍受次数、原会话与租约检查限制；官方会话无法恢复时报告失败，不假称 resume。

网络和模型调用不具备跨系统 exactly-once 保证。持久队列允许重复传输，接收事务负责去重和副作用一致性。旧信箱未声明 task protocol 2 时保留新任务出站队列并明确报升级要求。

## 材料快照

先由 Codex 原生工具在授权根目录内发现候选；Rust 复制所需 UTF-8 脚本/文档、复用内容寻址 blob 存储，再从独立材料目录启动正式分析。发现与分析的物理范围不同，所以明确建立新执行/新会话；同一范围内的问答续接使用真实 `codex exec resume`。

材料目录位于个人数据库旁的 `*.task-materials/<snapshot-id>/root-N/相对路径`。文件只读，保留根目录内的相对结构。清单保存成员、原相对路径、快照路径、SHA-256、字节数和采集时间。复制检查路径越界、符号链接、文件身份与修改时间、UTF-8/二进制以及总量；分析执行仅能读取固定材料，不能绕回实时源目录。原文件后续改动不会改变旧分析依据。每次后续执行仍检查原白名单有效性及材料/blob 哈希；撤销白名单不能借快照继续读取。

默认最多 40 个文件、合计 2 MiB。不自动拷贝整个目录、大型数据集或 HOME。材料缺失、超限、复制期间变化或缺少依赖会阻塞或追问，不静默截断。纯路径清单明确为实时发现记录，包含时间与执行证据，不能冒充固定版本内容分析。

原始材料保留在所属成员机器。信箱承载必要上下文、相对引用、结果和摘要；模型上下文仍可能包含授权文本，不能将“材料留在本地”解释为文本从不离机。归档与重开不删除旧证据。

本次兼容官方 Codex CLI 0.160.1：自动任务设置 `project_doc_max_bytes=0`，避免启动时加载权限范围外的可变目录指令；任务指令经 `get_task` 明确提供。只读、禁网、凭据与数据库保护仍在。配置含义参见 [OpenAI 配置文档](https://learn.chatgpt.com/docs/config-file/config-reference)。

## 信箱调度

信箱进程内持久调度，不依赖外部 cron。服务启动时保存以下配置，内部时间为 UTC，TUI 使用本地时间：

```toml
[schedule]
meeting_interval_secs = 7200
meeting_wait_secs = 300
meeting_max_rounds = 2
timezone = "America/Denver"
daily_time = "18:00"
```

每次例会采用一轮事实汇报并汇总，最多两轮的配置作为上限。在线 agent 即使没有新进展也汇报完成、依据、阻塞与下一步；无需重新调用 Codex。A 的任务历史和详情接收汇总，A 离线时事实保留，等待其上线处理。缺席和后续补报可区分。需要处理的任务只报卡点；完成/取消/待确认任务不再开执行例会。

会议/日报有稳定系统事件 ID 与独立认证接口，不能由普通成员文本冒充。重启或长时间离线合并过期邀请与未读汇总，保留合并记录。服务器不能唤醒关机的个人电脑。

日报仅投递给参与者，显示最后观测到的事实、状态更新时间、负责人及任务编号。夏令时重叠使用第一个有效时间，缺失时段使用随后第一个有效分钟；同团队日期、同收件人一次。补发合并为最新摘要并标注区间。只有自己参与的任务也有经过认证的事实出站队列，进入相同调度，不产生自己的收件消息或第二张任务卡。

个人端自动化限制：

| 设置 | 默认 | 含义 |
| --- | --- | --- |
| max_rounds | 12 | 每修订的 Codex 轮数与自动协调决策各自的上限 |
| max_no_progress | 3 | 重复问题/结果或同一候选反复升级追问的上限 |
| max_retries | 3 | 协调工作尝试和无副作用格式纠错的上限 |
| max_files | 40 | 单次材料快照文件数 |
| max_bytes | 2097152 | 单次材料快照总字节数 |

`xxassxx --db DB app task-limits` 查看；`app task-limits --input limits.json` 更新完整 JSON。轮数允许 1–100；无进展/重试 1–10；文件数 1–40；字节数最多 20 MiB。模型调用本身失败/结果不确定不会伪装成成功或盲目重放。

### 2026-10-07 后续修复：执行成员、聊天目标和重试

任务执行成员由发起人与参与者共同确定，在各机器上得到相同结果。创建执行和实际读取前均检查成员；旧版遗留的错误本机执行也会被拒绝。补查通过原问题关联发回执行方，保留历史，不将调查要求伪装成事实答案。

TUI 选中任务后仅显示该任务消息；后台命令改变所属任务时继续跟踪到处理结束，切换任务或对话会清理旧的问题选择。普通聊天不触发 answer_task。需要回答时按 CtrlB 明确选中问题。

远程执行失败显示为需要处理，发起人 CtrlY 将重试送回原执行方。旧版远程错误状态也兼容此入口；不自动扩大白名单、不重置执行预算。新配置每轮默认等待时间从 180 秒调整为 600 秒；已有个人配置不由代码静默覆盖。内部事件类型改为中文标签，确认卡不再直接打印 JSON，执行方收到、材料找到、结果收到都会发送进展消息。模型被要求先给具体发现和结论，避免对用户讲内部协调过程。

后续实际终端验证：扫描与原 MOOSE 进展查询均经 Mac→Trader→Lakota 完成，包含远程显式重试与原 Codex 会话续接。107 项最终完整回归通过；实际结果及限制见 [本轮证据](task-routing-fix-evidence.json) 与接续摘要。普通任务追问仅提供当前状态、当前问题、当前结果和近期对话，不再重复灌入全部旧执行和协调记录，并将用户最新要求作为独立消息传给模型，避免旧报告压过当前追问；可在完成的任务里继续询问解释。
