## 材料如何分配

| 位置 | 材料 | 该端知道什么 |
| --- | --- | --- |
| A / Trader | `a/protocol.json` | 校正公式、三个批次的参数、判定阈值、报告规则；不知道实际测量批次和读数 |
| B / Lakota | `b/measurements.csv` | 8 个样本的三次原始读数及实际批次；不知道校准参数和判定阈值 |
| 本地验收电脑 | `acceptance/expected.json`、检查程序 | 标准答案；不加入任何任务授权、不传给两个模型 |

`case.json` 是现有 `ssh_workflow.py --case` 可直接使用的清单，内嵌上述两份材料及各端任务描述。脚本只把各端自己的正文发布到对应机器，各端执行器只能通过任务 MCP 读取自己的授权文件。材料与目标中没有标准答案、预计通过人数或失败样本编号。A 的方案还包含本次未用到的 r9 批次，A 只需回答 B 实际询问的批次。

现有演示入口会以 `--text` 发布正文，所以不可变版本中的路径统一为 `record.txt`；`protocol.json` / `measurements.csv` 是对象标题和原始文件名。引用应使用实际 MCP 返回的路径、对象、版本与哈希。

## 自然发生的往返

1. A 读取自己的方案，向 B 发出质控请求。
2. B 读取 CSV，发现实际批次为 p7 和 q4，向 A 询问相应校准和判定规则。
3. A 恢复原会话，查阅本地方案并回答所需规则。
4. B 恢复原会话，计算逐样本结果并回传。
5. A 恢复原会话，复核、汇总并保存带两端来源的最终 JSON。

澄清与回答的具体文字由模型生成；不要求逐字匹配。脚本不会逐轮代发回答或填入结果。
